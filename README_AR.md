# NOVA ARENA Physics LAB — الحزمة المركزية

هذه الحزمة تحافظ على تطبيق HTML الحالي وتضيف أساس الربط السحابي، ونشر النسخ، وبوابة متسابق عبر رابط، مع صلاحيات في Supabase. لا تصبح المزامنة الحقيقية جاهزة إلا بعد إكمال الإعدادات أدناه.

## محتويات الحزمة
- `index.html`: واجهة التطبيق الحالية مع لوحة اتصال سحابي، حفظ المسودات، نشر نسخة عامة، وضع متسابق عبر `?view=player`.
- `cloud-config.js`: عنوان Supabase والمفتاح العام (يجب تعبئتهما).
- `supabase_setup.sql`: الجداول وسياسات RLS.
- `supabase_functions/join-competition.ts`: دالة انضمام برمز الفريق.
- `supabase_functions/submit-answer.ts`: دالة إرسال إجابة للسؤال الجاري.

## المرحلة 1 — إنشاء مشروع Supabase
1. أنشئ مشروعًا من https://supabase.com/dashboard
2. من Project Settings > API انسخ Project URL والمفتاح publishable/anon.
3. افتح `cloud-config.js` بمفكرة Windows، واستبدل:
   - `https://YOUR-PROJECT.supabase.co`
   - `YOUR-ANON-OR-PUBLISHABLE-KEY`
4. لا تضع `service_role` في هذا الملف مطلقًا. المفتاح العام ظاهر للزوار بطبيعته؛ الحماية تكون بسياسات RLS والدوال.

## المرحلة 2 — إنشاء الجداول
1. في لوحة Supabase افتح SQL Editor > New query.
2. انسخ محتويات `supabase_setup.sql` والصقها ثم اضغط Run.
3. من Authentication > Users أنشئ مستخدمًا للمسؤول ببريد وكلمة مرور.
4. انسخ UUID الخاص بالمستخدم، ثم نفّذ في SQL Editor:
   ```sql
   insert into public.admin_profiles(user_id, role)
   values ('PASTE-AUTH-USER-UUID-HERE','admin');
   ```
5. أنشئ حسابًا آخر بدور `operator` إذا أردت مشغّلًا لا يستطيع نشر النسخ.

## المرحلة 3 — نشر دوال المتسابق
تحتاج Edge Functions إلى Supabase CLI أو محرر الدوال في لوحة Supabase. أنشئ دالتين بالاسمين:
- `join-competition` وانسخ محتوى `supabase_functions/join-competition.ts`
- `submit-answer` وانسخ محتوى `supabase_functions/submit-answer.ts`

تأكد أن متغيرات البيئة الافتراضية للدوال تشمل `SUPABASE_URL` و`SUPABASE_ANON_KEY` و`SUPABASE_SERVICE_ROLE_KEY` من إعدادات Supabase. مفتاح الخدمة يبقى داخل بيئة الخادم فقط.

## المرحلة 4 — رموز انضمام الفرق
يجب أن تتطابق قيمة `team_id` مع معرف الفريق في قسم الفرق داخل التطبيق. غيّر الرمز قبل الاستخدام، ثم أضف رمزًا لكل فريق. مثال:
```sql
insert into public.team_join_codes(competition_slug,team_id,team_name,code_hash)
values ('nova-arena','1','الفريق الأول',
  encode(digest('CHANGE-THIS-TEAM-CODE','sha256'),'hex'));
```
كررها لكل فريق برمز مختلف وطويل. لا تستخدم الرمز المثال في مسابقة حقيقية.

## المرحلة 5 — تشغيل التطبيق
1. ضع `index.html` و`cloud-config.js` في المجلد نفسه.
2. انشرهما على استضافة HTTPS مثل Netlify أو استضافة ثابتة أخرى. لا تعتمد على فتح `index.html` محليًا لتجربة Edge Functions.
3. افتح رابط الموقع، واضغط زر السحابة في أعلى الواجهة.
4. سجّل دخول المسؤول، ثم احفظ مسودة واضغط «نشر التغييرات».
6. بوابة المتسابق: أضف `?view=player` إلى رابط الموقع، مثل `https://YOUR-SITE.netlify.app/?view=player`. يكتب المتسابق رمز فريقه ثم يرسل إجابته.
7. يجب أن تكون المسابقة منشورة وأن تكون الجولة الحالية `running` عند قبول الإجابات. ابدأ الجولة من واجهة المسؤول ثم اضغط نشر حتى تنتقل حالة الجولة المنشورة إلى بوابة المتسابق.

## مهم جدًا قبل بطولة حقيقية
- لا تنشر أي نسخة قبل التأكد من أن `published_payload` لا يحتوي على `answer` أو أي مفتاح إجابة صحيح. واجهة النشر في هذه الحزمة تنشئ نسخة عامة منفصلة عن المسودة الخاصة.
- بيانات الأسئلة والفرق والنتائج القديمة تبقى محليًا إلى أن تحفظها كمسودة أو تنقلها إلى المشروع السحابي.
- لوحة «استيراد إجابات الفرق» تسحب الإجابات غير المعالجة وتحسبها على نسخة المسؤول الحالية. اختبرها جيدًا على نسخة تجريبية قبل الاعتماد عليها؛ لا تستخدمها بالتزامن مع احتساب النقاط يدويًا لنفس الإجابات.
- هذا إصدار تأسيسي يحتاج اختبارًا على جهازين قبل الاستخدام الفعلي. النشر لا يحدث تلقائيًا عند كل تعديل؛ المطلوب هو الضغط على «نشر التغييرات» حسب طلبك.
- QR: بعد نشر الموقع، أنشئ رمز QR لرابط المتسابق، أو استخدم أي مولّد QR موثوق. لا تضع رموز الفرق السرية داخل QR عام واحد.
- مفتاح Supabase العام ليس سرًا؛ كلمة مرور المسؤول ومفتاح service_role هما اللذان يجب حمايتهما.

## استكشاف الأخطاء
- `Invalid API key`: راجع `cloud-config.js`.
- لا يمكن تسجيل الدخول: تأكد أن المستخدم موجود في Authentication وأنه مضاف في `admin_profiles`.
- لا تظهر التحديثات: تأكد من نشر النسخة وأن جدول `competition_publications` مضاف إلى Realtime.
- رمز الفريق لا يعمل: تأكد من وجود hash صحيح في `team_join_codes` وأن الرمز المدخل يطابق النص الأصلي.
